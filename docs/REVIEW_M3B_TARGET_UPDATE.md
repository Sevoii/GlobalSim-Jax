## Source-backed transition criteria

1. **Validate immutable observations and array alignment.** The source asserts `live.len() == cached.len()`. Retain one stable owner-excluded peer slot mapping across cached horses, live horses, visible indices, front identity, target indices and blocker scans. Collection cache observations are read-only inputs: update must not rewrite cached owner/peers, `visible`, side room, cached front snapshot or its parameter snapshot. Represent padded rows with a count/mask and never let inactive entries participate.
2. **Resolve front identity from an exact cache key.** Reuse `front_cache` only when owner position bits, owner lane bits, `front_distance` bits and `front_lane` bits all exactly match the current context/parameters. Otherwise query the current owner point against cached peer points with the source `front_index_iter` condition and tie behavior. The fallback result is local to this update; it does not replace the stored `front_cache`. Test one-bit changes and signed zero to prove the bitwise decision, and prove fallback does not mutate cache observations.
3. **Reset and update prior inward-permission edge state.** Set `skip_passing = false` at each invocation. Read `can_in` as false when no side cache exists. Compute `inside_opened` from prior `previous_can_in == Some(false)` and current `can_in`, then store `Some(can_in)` for the next call. Do not conflate absent prior value with false.
4. **Use mixed cached/live values in eligibility.** For peer `i`, source computes position gap `(cached[i].position - current_owner.position)` and speed gap `(current_owner.speed - cached[i].speed)` in f32, then widens those rounded results to f64 for the overtaking helper. It compares the current owner's target with `live[i].target` and `live[i].speed`, narrowed to f32 inside `overtaking`. The direct-blocker flag is `front == Some(i)`. Keep this mixture and operation order; do not use live position/speed for cached-gap inputs or cached target/speed where live fields are sampled.
5. **Preserve blocker predicate and short-circuit.** `is_target_with_block_check` narrows the f64 inputs to f32, rejects `gap < -1`, handles direct blockers using only `other_speed < owner_target`, then checks inclusive `[1,20]`, positive speed gap, and `gap / speed_gap <= 15`. It compares live other speed and live other target against owner target. Only when those two results disagree does it invoke `has_front_blocker`; the result selects which comparison applies. `has_front_blocker` tests cached peers followed by the current owner point, using strict positive/front-distance bounds and inclusive mixed-precision front-lane limit. Preserve this lazy branch and iterator construction. The current owner must remain included for source fidelity, but do not demand an eligibility-output witness caused by that owner: for a finite indirect candidate, its positive gap places the candidate ahead of the owner, so the owner cannot be a positive-gap front blocker of that candidate; direct-front candidates skip this blocker query. Instead, assert helper inclusion/behavior separately (for example, an oracle-only diagnostic) and use a qualifying cached-peer blocker to witness an actual eligibility result change.
6. **Keep the exact target list mutation order.** First discard prior indices `>= peer_count` (source `usize` indices cannot be negative). Save the resulting old-entry count. Visit `visible` in its stored order and append each missing eligible index. Then revalidate only those original retained entries, preserving their relative order; newly appended entries are kept based on the identical eligibility query already performed. Finally append the front index if present and not already present, without requiring visibility or overtaking eligibility. Do not sort, deduplicate preexisting duplicates, or move the appended front ahead of visible candidates.
7. **Match cooldown and sticky force-check.** If targets are nonempty, assign `cooldown = parameters.cooldown`. Otherwise, only when current cooldown is strictly positive, subtract f32 `dt`; do not clamp an overshoot, so a negative result is retained. If the result is `<= 0`, set `force_check = true`. Do not clear `force_check` in this method; it is sticky here. With no targets and nonpositive cooldown, leave cooldown and force-check unchanged.
8. **Preserve unrelated persistent state.** Apart from targets, cooldown, force-check, `previous_can_in`, and the per-call reset of `skip_passing`, do not change force-in, extra-outward, cache data, side/front snapshots, or other lifecycle state. Since the destination uses a standalone functional state return, tests must compare every input and output leaf to establish this transition. Do not claim collection's full `TargetState` lifecycle mutation semantics unless the represented state actually contains them.
9. **Checked API and bounded capacity.** Require x64 where the f64 bridge is used. Validate shapes, dtypes and integer ranges before JIT; reject nonfinite, f32-overflow and unsupported nonzero-subnormal operands and derived comparison values. Validate owner/capacity/count consistency and target/visible/front indices without unsafe gathers. Drop source-stale prior targets by peer count, while clearly rejecting indices that exceed the representable fixed-capacity state. Never inspect poisoned padding. Include zero/full capacity and malformed index/state cases.
10. **Differential evidence.** Use an independently compiled source-extracted `update_targets` body, unchanged original overtaking module, and copied `has_front_blocker`, with extraction boundaries, pinned revision and data provenance documented. Use multistep traces and compare every persistent state/cache field, eager and JIT, plus scan/vmap isolation and checked-boundary behavior. Cases must discriminate cached versus live fields, visible append order, old-target revalidation, unconditional front append, cache reuse versus one-bit-key fallback, a cached-peer blocker that changes eligibility, cooldown overshoot/stickiness, and lifecycle-field preservation. Verify that the extracted helper includes the current owner, but treat that as helper/extraction evidence rather than requiring an impossible current-owner-only eligibility output witness. Source-extracted evidence covers only this update subset.

### Intermediate static findings (draft only)

1. **High — confirmed checked-boundary source mismatch from root's original-Rust audit.** `update_targets_checked` validates cache-peer differences against the current owner (`cached_gap`/`current_gap`) and current-owner front narrowing, but `_has_front_blocker` also subtracts candidate peers from other cached peers and computes `front_lane_limit` on those pairwise gaps. Root reports this reproducer: owner `[-10,.2,24,25]`; cached peers `[min_normal,.4,20,26]` and `[nextafter(min_normal,+inf),.4,20,26]`; live peers `[100,.4,26,24]` and `[100,.4,26,26]`; default collected cache, empty targets, `dt=.1`, cooldown `.5`. Checked JAX accepted it and returned target index `[0]`. Root then compiled a temporary audit harness with the original extracted Rust `update_targets` under `rustc --edition=2021 -O`: the blocker gap's bits were `1` (positive minimum subnormal), and the original-source assertion that `targets == []` passed. This confirms a behavior mismatch, not just a conservative-domain omission: Rust sees the subnormal peer-to-peer blocker and excludes peer 0, while the current JAX path accepts peer 0 after the checked boundary lets the pairwise gap reach XLA. Root reports the temporary audit files were cleaned and no implementation/reference files changed. Before acceptance, reject this source-evaluated pairwise subnormal at the checked boundary (or implement source-faithful handling) and retain both the explicit checked rejection regression and the independently source-produced empty-target expected result. More generally, validate pairwise active-row differences and cone narrowing or make the kernel's evaluation domain/source short-circuit behavior safe. The JAX kernel evaluates `blocked = vmap(blocker_for)(...)` for padded candidate rows before eligibility selection, unlike Rust's lazy blocker closure, so account for arithmetic the JAX graph actually evaluates.

2. **High — checked state/cache structure and leaf dtypes are under-validated.** The wrapper checks top-level owner/live shapes and only a subset of numeric leaves. It does not establish that `cache.owner` is `[4]` f32, `cache.peers` is `[32,4]` f32, `cache.visible` is `[32]` bool, cache front/parameter scalars have the expected f32/int32 forms, or `cache.count` and `target_count` are scalar int32 values before converting them with Python `int`. It similarly does not validate scalar boolean dtypes for `force_check`/`force_in`/`skip_passing`, the `previous_can_in` sentinel domain, or the target buffer's int32 dtype. Malformed shapes/dtypes may fail during `.view`, indexing or tracing instead of raising a clear checked-boundary `ValueError`, and widened integer leaves can leak through the returned state. Validate every state/cache leaf and either canonicalize to the declared dtype or reject noncanonical forms before invoking JAX. Include wrong-shaped arrays, bool/float counts, int64/overflow indices, and invalid flag/sentinel values.

3. **Moderate — initializer accepts infinite `extra_outward`.** NaN is the documented encoding of Rust `None`, but the initializer currently checks only numeric scalar shape/type for `extra_outward`; unlike cooldown, it does not reject infinity. Permit the NaN sentinel and finite f32 values, reject +/-infinity and finite values that overflow f32 narrowing. Add checked constructor cases. (The earlier target-index int32 narrowing issue is resolved in the inspected code: range validation precedes assignment into the int32 padded buffer.)

4. **Moderate — checked path validates poisoned inactive padding as meaningful input.** `arrays` finiteness checks and `narrowed`/subnormal checks cover every row of fixed `[32,4]` cache/live buffers, including rows at or beyond `cache.count`; the kernel's eligibility and blocker predicates mask inactive peers. If padded tails are intentionally unspecified, canonicalize/ignore those tails before numeric validation and demonstrate poison independence. Otherwise make zero/finite canonical padding an explicit public checked-input requirement and test its rejection, while ensuring the unchecked kernel still cannot let padding change outputs. Avoid leaving the checked contract ambiguous.
