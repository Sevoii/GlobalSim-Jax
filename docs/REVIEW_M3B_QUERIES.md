# M3b standalone query helpers — source-backed review criteria

**Scope:** `retail_lane::side_room`, `retail_lane::is_visible`, and public `overtaking::is_target` only, at pinned Rust revision `58da7bc4693d9aa8f6340e348cba1c5b5fb5a856`. This is a preliminary source review and acceptance checklist, not implementation acceptance. Keep accepted sort/overlap/MoveState and M3a contracts unchanged.

## `side_room` exact behavior

Source: `src/retail_lane.rs:542-578`; types `Row`, `BlockParameters`, `SideRoom` at `8-14`, `455-480`.

- Initialize `can_in = owner.lane > 0.0001_f32`, `can_out = owner.lane < max_lane`, `in_space = owner.lane`, `out_space = max_lane - owner.lane`; do not replace strict rail comparisons with inclusive ones.
- Traverse the supplied peer rows in their original order and report blocker index in that same supplied-row indexing. The helper does no owner exclusion or finisher filtering; those are caller-list concerns. Do not silently remove peers or sort them.
- Skip a peer when `abs(peer.position - owner.position) >= side_distance`; equality is excluded. For inner peers (`peer.lane - owner.lane < 0`), always update `in_space = min(in_space, -gap)`, even when the peer is outside `side_lane`. If `-gap < side_lane`, set `can_in=false` and overwrite `inner_blocker` and its index. This intentionally retains the **last qualifying inner peer**, not the nearest. For outer peers (`gap > 0`), always update `out_space = min(out_space, gap)` and set `can_out=false` only for strict `gap < side_lane`. Same-lane peers (`gap == 0`) affect neither side.
- Keep every subtraction, absolute value, `min`, comparison, and result field in f32 source order. Return both booleans, both spaces, blocker lane and supplied-peer index. Map `Option` to an explicit JAX-safe absence pair (recommended index `-1` plus lane `NaN`, or a separate validity flag); document it and ensure no consumer gathers with `-1`.

## `is_visible` precision and edges

Source: `src/retail_lane.rs:484-499`.

- Return false for `vision <= 0` or unless `gap` lies in the inclusive f32 range `[0, vision]`; negative/behind gaps and values beyond vision are excluded. `lane_gap` is compared by absolute value and the final edge is inclusive.
- Preserve the f32 `ratio = gap / vision` store before widening. Width is `((ratio as f64 * 0.6388888955116272_f32 as f64 + 0.1111111119389534_f32 as f64) * 0.5) as f32`. Preserve the f64 literal evaluation, f32 coefficient values, addition/multiplication order, and final f32 store; do not simplify the cone expression or round its intermediates to f32.
- Preserve the source full-distance early bound `widest = ((1_f64 * 0.6388888955116272_f32 as f64 + 0.1111111119389534_f32 as f64) * 0.5) as f32`, rejecting `abs(lane_gap) > widest` before division. Test zero/negative vision, gap 0 and gap=vision, exact width and next representable f32 outside on both lane signs, and the source precheck edge.

## Public `overtaking::is_target` branch order and casts

Source: `src/overtaking.rs:2-5,10-27`. Public API accepts a final Boolean `directly_blocking` and `other_blocked`; do not emulate the private lazy callback, perform a hidden blocker scan, or add target policy.

- First cast `gap` and `speed_gap` from f64 to f32. Then reject only `gap < -1.0_f32`. If `directly_blocking`, immediately return `(other_speed as f32) < (owner_target as f32)`: this branch precedes ordinary `[1,20]` eligibility and ignores `speed_gap`, `other_target`, and `other_blocked`.
- Otherwise require the narrowed gap in the inclusive interval `[1.0_f32,20.0_f32]`, `speed_gap > 0.0_f32`, and `gap / speed_gap <= 15.0_f32`; division is f32 and equality at 15 remains eligible. If any condition fails, return false before target comparisons.
- Compute `blocked_result = f32(other_speed) < f32(owner_target)` and `unblocked_result = f32(other_target) < f32(owner_target)`. If equal, return that shared result regardless of `other_blocked`. If they differ, return `blocked_result` when `other_blocked` is true, otherwise `unblocked_result`. All target/speed comparisons use f32-narrowed operands; do not compare original f64 values.
- Checked host APIs should require scalar inputs, finite f64 values, actual booleans for both flags, and values whose f32 narrowing remains finite where the source narrows them. Preserve finite f64 underflow-to-f32-zero behavior because it is part of the source cast. State any remaining low-level preconditions explicitly; do not silently coerce arrays, clip counts, or accept NaN/inf through the checked boundary.

## Checked JAX and fixture acceptance

- Define a clear checked shape contract for side-room: owner `(position,lane)`, peer rows `[n,2]` with `n <= 32`, scalar finite f32 `max_lane` and block distances, no sorting/filtering, and no count truncation. If the kernel uses padded rows, require fixed capacity 32 and explicit integer `count in [0,32]`; the host wrapper may pad an unpadded row but must reject excess peers. Require x64 at checked boundaries for the f64 visibility expression and overtaking comparisons/casts as used by the port; never mutate global JAX config on import. Low-level kernels remain prevalidated.
- Emit every `SideRoom` field and exact float bits, including the absence sentinel. Independent Rust oracle/fixture cases must cover empty/full active rows, rail edges, exact and adjacent side-distance/side-lane f32 values, a peer that tightens space without blocking, multiple inner blockers where last differs from nearest, reordered peers proving index/order dependence, same-lane peers, and nontrivial padding. For visibility, include exact cone edges and adjacent f32 values. For overtaking, cover gap `-1`, `1`, `20`, speed-gap zero/positive, ratio exactly/just above 15, direct blocker bypass, equal-versus-different target comparisons, f64 values that narrow to same/different f32 values, and each Boolean combination.
- Expected values must come from unchanged pinned `overtaking.rs` and a documented mechanical extraction of the exact `side_room`/`is_visible` source operations, not from JAX. Record source revision, extraction boundary, oracle and fixture hashes. Compare all fields/flags in eager and JIT and real independent batches against scalar execution; include checked invalid shape/count/dtype/nonfinite cases. Verify the pinned source/hash manifest before fixture regeneration.

Keep source-compatible finite f64 underflow-to-f32-zero behavior; this finding concerns overflow to infinity. Source-order inspection otherwise found the kernels follow the preliminary criteria: side-room keeps the last qualifying inner row in supplied order with no owner/rail filtering; visibility stores the quotient in f32 before the f64 cone width; and overtaking applies the `gap < -1` then direct-blocker branch before its ordinary inclusive range/speed-gap checks. These are code-inspection observations only, not fixture acceptance.

This is an actionable finding on the initial wrapper snapshot. Recheck after Terra's validation fix; oracle/fixture boundary coverage and independent eager/JIT/batch review remain pending.

### Follow-up: narrowed nonzero subnormals are also outside the current checked contract

Coordinator reproduced two accepted-input divergences in this snapshot: `is_target_checked(1., 1., 2e-40, 5., 1e-40, True, False)` returns false in JAX although the Rust f32-narrowed comparison is true; `is_visible_checked(0., 0., 1e-40)` returns false in JAX although Rust keeps positive f32 vision and returns true. Both values are finite before conversion; JAX/XLA flushes the nonzero f32 subnormals during conversion/use. Thus post-cast `isfinite` alone does not establish a source-valid domain.

**Required checked-domain resolution:** either implement and independently verify source-compatible subnormal handling, or reject unsupported nonzero f32 subnormals at the checked API and state the same precondition on low-level kernels. Test just-below/at/above the minimum normal boundary, including the two regressions above. Preserve a finite f64 value that narrows all the way to f32 `+0` or `-0` as the source zero; do not reject every tiny f64 input by magnitude alone.

For `side_room`, input-only checks are insufficient because normal f32 owner/peer coordinates can subtract to a nonzero subnormal intermediate. If choosing rejection, check source f32-stored intermediates as well: owner-to-peer position delta, peer-to-owner lane gap, initial `max_lane - owner_lane`, and any resulting space values before allowing the JAX loop to consume them. Reject only nonzero subnormals (and nonfinite narrowed results), not source-zero values. For `is_visible`, also account for the stored f32 `gap / vision` ratio if it becomes a nonzero subnormal. For `is_target`, cover narrowed comparison operands and the f32 ratio where applicable. Add checked-boundary tests proving unsupported subnormals reject and underflow-to-zero remains accepted; low-level traced callers need a documented precondition unless the kernel emulates the source behavior.

The existing public overtaking flag validation remains correct: scalar Python/NumPy booleans are accepted and numeric stand-ins are rejected. This follow-up supersedes the prior finite-only suggestion: a checked wrapper must guard both overflow-to-infinity and unsupported nonzero subnormal values/intermediates before claiming source parity on its accepted domain.

## Bounded final snapshot review (2026-11-17)

Reviewed current `lane_queries.py`, both query test files, the current 20 side-room / 12 visibility / 20 overtaking fixture, and the mechanically extracted helper source. Focused command `.venv\\Scripts\\python.exe -m pytest tests/test_lane_queries.py tests/test_lane_query_checked.py -p no:cacheprovider -q`: **6 passed in 1.84s**. No full suite was run.

**Decision:** the low-level helper algorithms are accepted for the tested source domain, but the checked-query API/milestone is **not yet accepted** until the checked-input and fixture follow-ups below land.

1. **Checked side-room accepts boolean peer-coordinate rows.** `side_room_checked` rejects complex rows, but its row validation otherwise uses only `np.isfinite` (`lane_queries.py:105`); NumPy boolean arrays are finite and are silently converted to f32 coordinates. The planned checked domain is real coordinate rows stored as f32, not Boolean coordinates. Reject bool peer-position/peer-lane arrays with a clear `ValueError` (or explicitly define and test bool-to-coordinate coercion, which is not the selected contract).
2. **Add positive tests through each checked wrapper.** Current fixture tests exercise checked APIs mainly for rejection; there is no direct positive `side_room_checked` comparison to a frozen expected row or positive normal-domain `is_target_checked` comparison. Add checked-output assertions against the Rust fixture for representative side/visibility/overtaking rows, including supplied-order inner blocker/index and absent sentinel. Keep f64 values that narrow to f32 zero accepted; the current visibility-underflow check is useful but does not cover checked side-room/overtaking outputs.
3. **Add tests for the implemented subnormal-intermediate guard and all overflow paths.** The current side-room subnormal test rejects a peer coordinate that is itself subnormal, but does not exercise normal f32 owner/peer coordinates whose position delta, lane gap, or initial `max_lane-owner_lane` becomes nonzero subnormal. Add at least one such normal-input difference case. The implementation checks these intermediates (`lane_queries.py:122-123`) and should reject. Also add finite-f64-to-f32-overflow coverage for `is_visible_checked`; current tests cover original infinity and overflow in side-room/overtaking, but not that finite-overflow path.
4. **Add a discriminating comparison-narrowing witness and durable provenance.** The fixture has a gap just above 20 that narrows to the inclusive f32 boundary, but target/speed comparisons currently use ordinary exactly representable values. Add a Rust-generated case where distinct f64 target/speed values narrow to the same f32 comparison result and change the Boolean from direct f64 comparison. Record the pinned revision and hashes for `tools/lane_query_oracle.rs` and `tests/fixtures/lane_query_oracle.json` in `docs/ORACLE_PROVENANCE.json`; the current manifest search has no lane-query oracle/fixture entries.

**Verified in the implementation:** checked wrappers test post-f32 finiteness; the subnormal profile rejects nonzero f32 subnormal inputs and the side-room stored deltas/spaces while allowing finite f64 inputs that narrow all the way to signed zero. The public overtaking checked flags require scalar bool dtype. The low-level side-room loop preserves supplied order, last qualifying inner blocker, outside-rail values and no owner/finisher filtering; visibility keeps f32 ratio then f64 width arithmetic; overtaking preserves f32 narrowing and direct-before-range branch order. Coordinator independently rebuilt the current 20/12/20 oracle byte-identically and confirmed the exact side-room/visibility source blocks plus unchanged `overtaking.rs`; this supports the algorithm decision, but does not close checked API acceptance or the listed fixture/provenance gaps.

This decision is limited to standalone helpers. Supplied-target field integration, automatic target/pacing, remaining M3b/M3c, complete simulation parity, and GPU validation/performance remain unaccepted.
