# Independent moving-field Rust oracle

`moving_field_oracle.rs` is a restricted supplied-target schedule adapter, not a full engine run. Reference revision: 58da7bc4693d9aa8f6340e348cba1c5b5fb5a856. Original Rust checkout stays read-only.

The R state, front/rank/side snapshot and longitudinal body are retained from the accepted `field_tick_oracle.rs` extraction. The only added movement inside that body is an actual `lane_move_oracle::MoveState::step` call after the gate early return and before longitudinal speed/HP/position updates. The included `lane_move_oracle.rs` mechanically copies original MoveState code; included `lane_query_oracle.rs` mechanically copies original side_room. Both their helper functions and the adapter call unchanged retail_physics. Original retail_sort is included by path. The overlap manager body is mechanically copied from retail_lane.rs. Dependencies and all fixture hashes are in ORACLE_PROVENANCE.json.

Configuration: distance1200, exact dt f32 bits in fixture (0.066600002348423, inherited from M3a; not exact mathematical1/15), speed_stat1000, power1000, guts900, strategy1, unity aptitude/ground. MoveParameters are explicit f32 (.001,.3,.02,.05,1.5), max_lane1, first_move_point375, no modifiers/automatic targets/pacing/geometry. Synthetic initial states supply explicit prior minimum and lateral momentum/continuation; initialization is not claimed to be full retail initialization.

Wrapper adaptations retained from M2/M3a: finish on reaching/exceeding1200; complete all runner moves plus overlap on that crossing tick; then freeze the entire batch. Tick counts and per-runner timeout flags are wrapper state, not retail policy. Cases have cap100 except all_timeout cap3; fixture always stores8 rows, so terminal rows are frozen padding. The serialized state columns are named in the JSON. f32/f64 fields store unsigned raw bits; integer/Boolean fields store values. Observation channels are front index, front-gap f32bits, side-block Boolean, cached one-based rank, cached can_in/can_out, gate-open Boolean and gate fraction f64bits (NaN if absent). Observations are diagnostic metadata; whole-state freezing applies to serialized state, not a promise to retain every diagnostic observation.

Nine cases cover cached side permission, post-position overlap, cached rank, chained overlap, closed gate, partial gate, first finish, all timeout, and ordered live blocker speed. The first three include counterfactual `witness` values calculated by the same original source helpers under the incorrect snapshot choice. Each correct/wrong lane bit pattern differs; the correct lane equals the actual trace state. Thus the witnesses establish sensitivity to ordering, not merely trace length. The partial-gate case uses full lateral dt; the closed-gate case retains target/momentum/timer despite manager lane correction. First-finish advances later runners before freezing. All-timeout retains nonzero blocking timers/continuation/flags for freeze checks.

Regenerate only after verifying pinned revision/source hashes. Build with `rustc --edition=2021 -Awarnings -O tools/moving_field_oracle.rs -o <temporary executable>`. Capture executable bytes using Python subprocess.check_output and Path.write_bytes; avoid PowerShell redirection encodings. Compare output byte-for-byte with tests/fixtures/moving_field_trace.json. Do not replace expected data with JAX output or simplified movement equations.


The serialized moved Boolean is per-pass wrapper telemetry: it resets false on a gate-skipped row. The retail sticky moved_lane_this_tick field is consumed by lane-speed skill receivers, which this profile explicitly excludes. This adapter does not claim that receiver/controller state. All physical/lateral stored state and the per-pass telemetry are compared in the declared restricted schedule.
